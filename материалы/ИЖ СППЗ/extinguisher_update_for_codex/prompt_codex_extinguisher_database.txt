Внести изменения в карточку элемента СППЗ типа "Огнетушитель".

Сначала обновить существующее ТЗ проекта ИЖ СППЗ под новые требования, затем внести изменения в программу. После этого проверить результат на создании, сохранении, повторном открытии и редактировании карточки.

Существующую логику автоматического расчета сроков перезарядки не изменять.

Требования к доработке:

1. Поле "Изготовитель"
- Сделать выпадающий список изготовителей.
- Добавить вариант "Другое".
- При выборе "Другое" показывать поле ручного ввода наименования изготовителя.
- Ручное значение сохранять в карточке конкретного огнетушителя.

2. Поле "Модель / марка"
- Список моделей должен зависеть от выбранного изготовителя.
- Использовать связку "изготовитель -> модель".
- Если архитектура интерфейса уже использует тип огнетушителя, сохранить совместимость, но модель должна однозначно зависеть от изготовителя.

3. Поле "Срок службы по паспорту"
- Хранить срок службы в годах, не в месяцах.
- Использовать числовое поле `serviceLifeYears`.
- Отображать пользователю в формате "10 лет", "15 лет", "20 лет" и так далее.

4. Автоматическое определение срока службы
- После выбора изготовителя и модели автоматически подставлять срок службы из справочника `fire_extinguisher_reference_v1.json`.
- Не определять срок службы только по типу огнетушителя.
- Не зашивать сроки службы непосредственно в интерфейс.

5. Расчет даты окончания срока службы
- Использовать поле "Дата изготовления".
- Формула: `дата изготовления + serviceLifeYears`.
- Использовать календарные годы.

6. Ручной режим
- Если пользователь выбрал "Другое" или модели нет в справочнике, не подставлять срок службы автоматически.
- В таком случае показать "Срок службы по паспорту: не указан".
- Разрешить вручную выбрать или ввести срок службы в годах.
- Ручное значение должно сохраняться для конкретной карточки.

7. Паспорт огнетушителя
- Использовать только официальные ссылки производителей, указанные в справочнике.
- PDF локально не хранить.
- Если у модели есть официальный паспорт, показать кнопку "Паспорт" с действиями "Посмотреть" и "Скачать".
- Если официальной ссылки нет, кнопку паспорта не показывать.

8. Структура справочника
- Использовать JSON как стартовый централизованный справочник моделей огнетушителей.
- Минимально учитывать поля:
  - `manufacturerId`
  - `manufacturerName`
  - `type`
  - `model`
  - `serviceLifeYears`
  - `passportUrl`
  - `passportSource`
  - `passportRevision`
  - `notes`

9. Ограничения
- Не менять существующую логику перезарядки.
- Не сохранять PDF-паспорта в базе приложения.
- Не показывать неофициальные документы и ссылки сторонних магазинов.
- Не изменять глобальный справочник автоматически из-за ручной правки одной карточки.

10. Проверка после реализации
- Проверить создание новой карточки огнетушителя.
- Проверить выбор изготовителя и модели.
- Проверить автоматическое появление срока службы.
- Проверить расчет даты окончания срока службы.
- Проверить работу варианта "Другое".
- Проверить сохранение карточки.
- Проверить повторное открытие карточки.
- Проверить редактирование существующей карточки.
- Убедиться, что логика перезарядки работает без изменений.
