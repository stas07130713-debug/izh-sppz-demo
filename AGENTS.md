# AGENTS.md — инструкция для любого ИИ или программиста, открывшего этот проект

Прочитай этот файл целиком, прежде чем менять что-либо. Он короткий.

## Что это за программа

**ИЖ СППЗ** — интерактивный журнал систем противопожарной защиты. Настольная программа для российских предприятий. Пользователь загружает план здания, размещает на нём противопожарное оборудование, а программа ведёт журнал эксплуатации и следит за сроками проверок по требованиям ППР РФ №1479, ГОСТ и СП.

Ключевой принцип продукта: **план и журнал — два представления одних и тех же данных.** Объект существует в одном экземпляре, в одной строке базы. У плана нет своей таблицы объектов.

Проектная документация — в `docs/`. Решения — в `docs/adr/`. Читай их, прежде чем спорить с архитектурой.

## Устройство проекта

```
packages/
  contracts/            @izh/contracts   — типы и интерфейсы. Единственное, что видят движки.
  core/                 @izh/core        — сценарии работы. Не знает ни о хранилище, ни об интерфейсе.
  engine-plan-source/   @izh/engine-plan-source — движок E1: PDF → подложка плана.
  desktop/              @izh/desktop     — оболочка Electron: окно, файлы, мост, интерфейс на React.
```

Интерфейс пока живёт внутри `desktop/src/renderer`. Когда он вырастет, его вынесут в отдельный
пакет `@izh/ui`; сейчас отдельный пакет был бы пустой обёрткой.

Разрешённое направление зависимостей — только сверху вниз:

```
desktop  →  core  →  contracts
   │                     ↑
   └──→  engine-plan-source ┘
```

Движок не зависит от ядра, ядро не зависит от движка. Оба знают только `contracts`.
Связывает их оболочка: `desktop/src/renderer/src/deps.ts` подставляет ядру нужный движок
и переходники к хранилищу.

Программа устроена как **ядро + сменные движки**. Ядро определяет, что такое объект и где он хранится, и меняется редко. Движки вычисляют и интерпретируют, и меняются часто.

Всего движков по проекту семь, сейчас реализуется первый:

| Код | Движок | Состояние |
|---|---|---|
| E1 | Подложки и распознавание планов | **в работе** |
| E2 | Автоматическая расстановка объектов | не начат |
| E3 | Регламенты и сигналы о состоянии | не начат |
| E4 | Конструктор типов объектов | не начат |
| E5 | Геометрические проверки | не начат |
| E6 | Отчёты и печатные формы | не начат |
| E7 | Импорт данных из Excel | не начат |

## Правила, которые нельзя нарушать

Это не стилистические пожелания. Нарушение любого из них ломает замысел архитектуры.

1. **Движок ссылается только на `@izh/contracts`.** Не на `@izh/core`, не на другой движок, не на интерфейс, не на Electron. Если движку что-то нужно — это передаётся ему параметром.
2. **Движок не пишет в базу и не трогает файловую систему.** Он получает данные и возвращает результат. Сохраняет ядро. Поэтому ошибка в движке физически не может испортить данные.
3. **Движок детерминирован.** Одинаковый вход — одинаковый выход. Текущее время, случайные числа и настройки передаются параметрами, а не берутся изнутри. Без этого невозможны воспроизводимые тесты.
4. **Интерфейс не обращается к базе и к файлам напрямую.** Только через сценарии ядра.
5. **Никакой магии.** Без фреймворков внедрения зависимостей, без декораторов, без кодогенерации, без метапрограммирования. Обычные функции и обычные интерфейсы с явной передачей зависимостей.
6. **`any` запрещён.** TypeScript в строгом режиме.
7. **Файл до 300 строк.** Больше — разбивай.
8. **Комментарии к предметной логике — на русском**, со ссылкой на пункт нормативного документа. Пример: `// Перекатка рукавов не реже 1 раза в год — п. 50 ППР РФ №1479`.
9. **Ни одно нормативное требование не зашивается в код.** Сроки, периодичность, пункты документов живут в данных (пакет правил), а не в `if`.
10. **Физического удаления данных нет.** Только пометка о выводе из эксплуатации. История не удаляется никогда — это требование законодательства к журналу эксплуатации.

## Чего делать нельзя

- Добавлять зависимость движка на другой движок или на ядро.
- Заменять простое решение «более правильным» фреймворком.
- Хранить абсолютные пути к файлам в данных.
- Использовать целочисленные автоинкрементные ключи. Только UUID — программа будет работать на сервере с несколькими пользователями.
- Писать даты регламентных событий как `Date` со временем и часовым поясом. Регламентные даты — это календарные даты, строка `ГГГГ-ММ-ДД`.
- Удалять или «упрощать» проверки целостности данных.

## Как запустить

```
npm install
npm run dev
```

Собрать и запустить собранное:

```
npm run build
npm run preview --workspace @izh/desktop
```

## Как проверить себя перед тем, как сказать «готово»

```
npm run check
```

Команда прогоняет проверку типов по всем пакетам и все тесты. Если она красная — работа не сделана.
Линтер будет добавлен отдельным шагом; пока его роль выполняют строгие настройки TypeScript.

Отдельно: у каждого движка есть эталонные тесты вида «вход → ожидаемый выход». Они и есть спецификация поведения. Если ты меняешь движок и тест краснеет — ты либо сломал поведение, либо обязан осознанно обновить эталон и написать в описании изменения, почему.

## Если сомневаешься

Сомневаешься в предметной области (пожарная безопасность, нормативы) — **не угадывай**. Ошибка здесь означает замечание при проверке МЧС у клиента. Спроси или оставь пометку `// ТРЕБУЕТ ПРОВЕРКИ:` с описанием сомнения.

Сомневаешься в архитектуре — читай `docs/adr/`. Там записано не только «как сделано», но и «почему именно так».
