# @izh/core — ядро

## Зачем нужен

Здесь живут сценарии работы программы: последовательности действий, из которых состоит польза для пользователя. Например, «сделать подложку из загруженного PDF» — это проверить тип файла, построить изображение, положить в хранилище исходный файл и изображение, записать сведения.

## Главное правило

Ядро **не знает**, где хранятся данные, как выглядит интерфейс и какой библиотекой разбирается PDF. Всё это приходит параметром `BackdropDeps`: движок, хранилище файлов, хранилище сведений, часы, генератор идентификаторов.

Благодаря этому:

- сценарий запускается в тесте с поддельными зависимостями и даёт предсказуемый результат;
- при переходе на сервер подставляются серверные реализации, и ни строчки здесь не меняется.

## Что обещает наружу

- `createBackdropFromPdf`, `createBackdropFromImage` — создание подложки;
- `calibrateByTwoPoints`, `calibrateByDrawingScale` — задание масштаба;
- тип `BackdropDeps` — что нужно передать сценарию.

## Что менять нельзя

- Добавлять зависимость на `@izh/engine-plan-source` или любой другой движок — **ни в коде, ни в тестах**. Ядро знает только `@izh/contracts`. В тестах используются поддельные реализации из `src/__tests__/test-doubles.ts`.
- Обращаться к файловой системе, к сети или к интерфейсу напрямую. Только через порты.
- Брать текущее время через `new Date()`. Только через порт `Clock` — иначе тесты станут невоспроизводимыми.
- Бросать исключения наружу. Сбой возвращается значением `Result`.

## Тесты

`npx vitest run packages/core`

Тесты описывают договорённость о том, что именно происходит при загрузке файла и при задании масштаба, включая поведение при ошибках: например, при сбое построения подложки в хранилище не должно остаться ничего.
