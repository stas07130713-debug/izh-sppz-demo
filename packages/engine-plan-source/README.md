# @izh/engine-plan-source — движок E1 «Подложки планов»

## Зачем нужен

Превращает загруженный файл — PDF или картинку — в подложку плана: изображение известного размера, для которого можно задать масштаб.

## Что обещает наружу

Один объект `planSourceEngine`, соответствующий контракту `PlanSourceEngine` из `@izh/contracts`:

- `detectKind` — что за файл, по содержимому, а не по расширению;
- `probePdf` — оглавление документа: страницы и их размеры. Быстро;
- `inspectPdfPage` — из чего состоит страница: чертёж это или скан. Небыстро, поэтому только по запросу;
- `estimateRasterSize` — каким получится изображение, без его построения;
- `rasterizePdfPage` — построение изображения подложки;
- `probeImage` — размеры картинки, загруженной вместо PDF;
- `metersPerPixelFromTwoPoints`, `metersPerPixelFromDrawingScale` — перевод точек в метры.

Дополнительно: `setPdfWorkerPort` — подключение рабочего потока pdf.js, вызывается один раз при запуске окна.

## Что менять можно

Всё внутри. Библиотеку `pdf.js` можно заменить целиком — снаружи виден только контракт. Пороговые значения в `content-signals.ts` и пределы размера в `scale-math.ts` — обычные константы, они подобраны по реальным материалам заказчика и могут уточняться.

## Что менять нельзя

- Добавлять зависимости на `@izh/core`, на интерфейс или на Electron. Разрешён только `@izh/contracts`.
- Читать и писать файлы. Движок работает с байтами, которые ему дали, и возвращает байты. Сохраняет ядро.
- Брать текущее время или настройки изнутри. Всё приходит параметрами.
- Бросать исключения наружу. Сбой возвращается значением `Result`.

## Где проходит граница с графикой

`scale-math.ts`, `content-signals.ts`, `detect-kind.ts` — чистая арифметика и разбор байтов. Работают где угодно, полностью покрыты тестами.

`raster.ts`, `pdf-probe.ts`, `pdfjs-setup.ts` — требуют графического холста и разбора PDF, поэтому работают только в окне программы. Обоснование — `docs/adr/ADR-003-подложка-плана.md`.

## Тесты

`npx vitest run packages/engine-plan-source` — эталонные таблицы «вход → ожидаемый выход». Это спецификация поведения. Покраснел тест — либо сломано поведение, либо эталон нужно обновить осознанно и с объяснением.
