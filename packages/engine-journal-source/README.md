# @izh/engine-journal-source — движок E7

## Зачем нужен

Читает чужие учётные журналы, чтобы их можно было перенести в программу. Сейчас понимает xlsx — именно в этом формате заказчик ведёт журнал сегодня.

## Что обещает наружу

- `journalSourceEngine` — реализация контракта `JournalSourceEngine` из `@izh/contracts`:
  - `detectKind` — похож ли файл на таблицу, по содержимому, а не по расширению;
  - `probeWorkbook` — какие листы есть в книге;
  - `readSheet` — строки одного листа текстом.

Значения ячеек отдаются **текстом как есть**. Даты в Excel лежат числами (46203 — это 30.06.2026), и превращать их в календарные — работа ядра: там есть проверки диапазона и отчёт о непригодных значениях вроде «дата не верна». Движок за ядро не решает.

## Почему распаковка написана своими руками

xlsx — это zip с XML внутри, а значит нужен deflate. Внешнюю библиотеку не берём:

- движок обязан работать и в окне программы, и в основном процессе, и в тестах — то есть не может опираться на `node:zlib`;
- браузерный `DecompressionStream` асинхронный, а контракт движка синхронный: ядро сопоставляет колонки без ожидания.

Формат deflate (RFC 1951) не менялся с 1996 года, и здесь ровно столько кода, сколько нужно для чтения xlsx. Это надёжнее, чем зависимость, которая обновляется и ломается.

## Что менять нельзя

- Ссылаться на `@izh/core`, на оболочку или на другой движок — только на `@izh/contracts`.
- Читать файлы с диска. Движок получает байты, файл открывает оболочка.
- Бросать исключения наружу. Битый файл заказчика — обычное дело, сбой возвращается значением `Result`.
- Превращать значения ячеек в даты и числа: это решение ядра, у него есть отчёт для пользователя.

## Тесты

`npx vitest run packages/engine-journal-source`

Проверяется распаковка deflate на всех трёх видах блоков и чтение xlsx, собранного прямо в тесте.
