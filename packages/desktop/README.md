# @izh/desktop — оболочка программы

## Зачем нужен

Всё, что связано с конкретной операционной системой и с показом на экране: окно, диалог выбора файла, хранение файлов на диске, интерфейс.

## Устройство

```
src/main/       фоновый процесс: окно, файлы, хранилище, мост
src/preload/    перечень действий, выдаваемых окну
src/renderer/   интерфейс на React
```

### Фоновый процесс

- `file-store.ts` — хранилище файлов с адресацией по SHA-256 содержимого;
- `backdrop-repository.ts` — сведения о подложках в файле JSON. **Временное решение**, на следующем шаге заменится SQLite. Заменяется только этот файл, потому что ядро работает через порт;
- `ipc.ts`, `channels.ts` — мост между окном и файловой системой. Это транспортный шов: сегодня вызов идёт в тот же процесс, завтра — по сети на сервер организации.

### Окно

- `deps.ts` — сборка зависимостей для ядра: подставляет движок E1 и переходники к хранилищу через мост. **Это единственное место, где части программы связываются друг с другом.** Здесь же создаётся рабочий поток pdf.js, потому что его создание зависит от сборщика, а движок не должен о сборщике знать;
- `App.tsx` — состояние интерфейса и связывание частей. Сам ничего не вычисляет;
- `components/` — представления.

## Безопасность

Окно не имеет доступа ни к файловой системе, ни к Node: `contextIsolation` включён, `nodeIntegration` выключен. Окну выдаётся только перечень действий из `preload`. Выполнение кода из PDF запрещено (`isEvalSupported: false`) — файлы приходят от посторонних.

## Почему пакет не помечен как ESM

Фоновый процесс и мост собираются в CommonJS. Так работает штатная защищённая песочница Electron и доступен `__dirname`. Окна это не касается — его собирает Vite.

## Что менять нельзя

- Обращаться из окна к файловой системе минуя мост.
- Класть бизнес-логику в обработчики событий интерфейса. Логика — в `@izh/core`.
- Хранить абсолютные пути к файлам в данных.
